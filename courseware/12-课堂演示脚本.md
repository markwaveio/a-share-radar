# 12 课堂演示脚本

## 20 分钟首次演示流程

目标：让学员在 20 分钟内看到「从一个 URL 到一张全市场表格」的完整链路。

---

### 1. 先讲定位（2 分钟）

```text
这不是一个选股软件，是把你的筛选标准固化成每日报表的流水线。
它的产出是候选池，不是买卖信号。
```

---

### 2. 演示数据源（5 分钟，全场最有说服力的一段）

**先跑能成功的**，让学员看到地基：

```bash
curl 'https://ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600000,day,,,5,qfq'
```

讲解：

```text
这就是行情 App 用的同一套公开接口。
param 里：sh600000 是浦发银行（sh=上海），day 是日线，qfq 是前复权。
返回 ["2026-08-07","9.260","9.210","9.290","9.140","565457.000"]
顺序是 日期,开,收,高,低,量 —— 注意是开收高低，不是常见的开高低收。
```

**紧接着跑挂掉的那个**，这是这一讲的高潮：

```bash
curl 'https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&klt=101&fqt=1&lmt=5&fields1=f1,f2&fields2=f51,f52,f53,f54,f55,f56'
```

写这份课件时它返回 `curl: (52) Empty reply from server`。讲解：

```text
这不是网络断了。TCP 和 TLS 握手都成功，服务端接了连接然后直接关掉，
一个字节都不回。同一时刻同一台机器上，东财的股票池接口是好的。

第三方接口没有服务承诺，它会在你毫无准备的时候挂掉。
整个项目的多数据源设计，就是为了这一刻。
```

**再跑第三条，讲最隐蔽的那种失败**：

```bash
curl 'https://push2delay.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&klt=101&fqt=1&lmt=5&fields1=f1,f2&fields2=f51,f52,f53,f54,f55,f56'
```

返回 **HTTP 200**、JSON 格式合法，但里面没有 K 线。
而且它"没有数据"的长相还会变——这两种两天内都出现过：

```text
{"rc":0,  ..., "data":{"code":"600000","klines":[]}}    rc=0 但 klines 空
{"rc":102,..., "data":null}                              rc 变了，data 直接是 null
```

```text
接口"可用"有四个层次：
    能连上 → 返回 200 → 业务码正常 → 真的有你要的数据

只验证前三层的代码，会在第四层安静地失败：
Excel 那一列全空，日志里一条错误都没有。

唯一可靠的判据：把你真正要用的那个字段取出来，看它是不是空的。
```

> 演示应变：如果东财当天恰好恢复了，把它当"曾经发生过"来讲即可 ——
> 接口时通时断本身就是要传达的事实。
> 如果腾讯那条也挂了，直接跑 `python3 run.py --task 1 --limit 5`，
> 看日志里它降级到哪个源，效果更好。

---

### 3. 跑一次链路自检（3 分钟）

```bash
cd /path/to/a-share-radar   # 换成你的克隆目录
python3 run.py --task 1 --limit 30
```

演示时指着日志讲：

```text
- 「全市场 A 股共 5547 只」   -> 股票池拉到了
- 「股票池过滤：5547 -> 30」  -> --limit 生效
- 「进度 30/30」              -> 并发扫描
- 「扫描完成：成功 30，失败 0」-> 这个失败数每天都要看
- 「已生成 .../01_KDJ全周期_...xlsx」
```

---

### 4. 打开 Excel，讲表头（3 分钟）

```text
两行表头：第一行是周期，第二行是 K值/D值/J值。
一共 32 列 = 2 + 10 个周期 × 3。
这个结构不是我们设计的，是需求 Excel 里给定的 —— 表头就是验收标准。
```

顺手演示筛选：**选中第 2 行**再开筛选（合并表头必须这样操作）。

---

### 5. 讲一个坑，建立信任（3 分钟）

```bash
python3 tests/test_indicators.py
```

指着 `test_kdj_matches_manual_recursion` 讲：

```text
KDJ 里的平滑不是移动平均，是递推：K = (2×前一日K + 今日RSV) / 3。
用 pandas 的 rolling().mean() 会算出差 10~20 的值，
而且看起来"像是对的" —— 这是最难查的一类 bug。
所以这个算法用手工递推的结果做了单元测试，改代码后必须重跑。
```

**这一步的目的不是讲技术，是让学员相信这些数字是可验证的。**

---

### 6. 手工对照验证（3 分钟）

```text
打开东方财富 App，找刚才表里的任意一只股票，
切到日线，看 KDJ(9,3,3)，和 Excel 里的「本日」K/D/J 对照。
差 0.01~0.05 正常，差 1 以上就有问题。
```

让学员自己挑股票、自己对照。**她亲手验证过一次，后面才会用。**

---

### 7. 跑全市场（演示启动即可，3 分钟）

```bash
python3 run.py --task all
```

讲解等待期间的日志：

```text
5500 只 × 6 个周期 ≈ 3.3 万次请求。
并发 12，限流 30 QPS，大概 5~10 分钟。
调高并发不一定更快 —— 被限流之后重试反而更慢。
```

---

### 8. 装定时任务（2 分钟）

```bash
./scripts/install_launchd.sh install
./scripts/install_launchd.sh status
```

```text
11:40 午盘批：只跑 KDJ，因为成交量和资金流要等收盘才完整。
15:15 收盘批：四个需求全跑，15 分钟缓冲是等资金流数据落库。
非交易日会自动跳过 —— 它去问上证指数今天有没有 K 线，
而不是维护一张会过期的节假日表。
```

---

## 课堂结束前检查

- 学员知道数据是从东方财富公开接口来的，不是黑盒。
- 学员亲手用 App 对照验证过至少一只股票的 KDJ。
- 学员知道「本日」在午盘批和收盘批不一样，而且知道为什么。
- 学员知道每天要先看「抓取失败」数。
- 学员知道空值代表数据不足，不代表 0。
- 学员知道参数改在 `radar/config.py`。
- 学员能说出「雷达的产出是候选池，不是决策」。

## 第二次课的演示（阅读方法）

用当天真实生成的四张表，走一遍第 03 讲的筛选闭环：

```text
04板块热度  -> 挑 2~3 个连续升温的方向
02放量TOP200 -> 在这些方向里找放量倍数 > 3 且 cv_range < 0.6 的
03升温TOP100 -> 确认消息面有没有跟上，注意先看基准期条数
01KDJ       -> 查月/周/日 J 值是否同向
最终缩到 10~20 只，写进 data/watchlist.txt
```

现场把 watchlist 写好，然后演示：

```bash
python3 run.py --task 3 --sentiment-universe watchlist
```

```text
这才是咨询量最实用的用法：不查全市场，只查已经筛出来的候选池。
又快又准，还避开限流。
```
