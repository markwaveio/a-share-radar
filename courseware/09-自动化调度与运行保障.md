# 09 自动化调度与运行保障

## 两个批次的时间设计

| 批次 | 时间 | 任务 | 为什么是这个时间 |
|---|---|---|---|
| midday | 11:40 | 只跑需求 1 | 11:30 午盘收盘 + 10 分钟缓冲，等东财数据落库 |
| close | 15:15 | 全部四个 | 15:00 收盘 + 15 分钟缓冲，资金流数据比行情晚出 |

**缓冲时间不是随便定的。** 15:00 整点去拉资金流，经常拿到的还是 14:xx 的数据。
课上要讲这个：自动化任务的时间点必须匹配**数据的可用时刻**，不是交易的结束时刻。

## 交易日闸门

非交易日跑一次是 3.3 万次无意义的请求。所以脚本第一步就是判断交易日。

**这里有个设计选择值得讲**：不维护本地节假日表。

```text
方案 A：本地维护 A 股节假日表
问题：每年要人工更新，忘了更新就会静默跑错，而且错得没有任何提示

方案 B：问数据本身 —— 拉上证指数最新日线，看日期是不是今天
优点：永远不会过期，交易所调休也自动跟上
```

项目用的是方案 B（`radar/trading_calendar.py`）。

还有一个细节：**判断不了的时候（网络故障）按交易日处理，继续跑。**

```python
# 宁可在非交易日多生成一份重复报表，
# 也不要在交易日因为网络抖动漏掉一次。
```

这类"失败时往哪边倒"的决策，在自动化系统里到处都是，要养成显式思考的习惯。

## launchd 怎么用

macOS 上定时任务用 launchd，不是 crontab（crontab 在 macOS 上会被系统限制）。

```bash
./scripts/install_launchd.sh install     # 安装并加载
./scripts/install_launchd.sh status      # 看有没有在跑
./scripts/install_launchd.sh uninstall   # 卸载
```

plist 文件装在 `~/Library/LaunchAgents/`：

```text
com.ashare-radar.midday.plist
com.ashare-radar.close.plist
```

### 两个 plist 里的关键设置

```xml
<key>RunAtLoad</key>
<false/>
```

**开机不补跑。** 因为错过的批次数据已经失去时效 ——
早上 9 点开机补跑昨天 15:15 的批次，会用今天的数据覆盖出一个错误时点的快照。

```xml
<key>PATH</key>
<string>$HOME/.local/bin:/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:...</string>
```

**launchd 的环境变量和终端不一样。** 这是最常见的"手动跑没问题，定时跑就失败"的原因。
课上一定要讲这一点，它能省掉 学员未来好几个小时。

## 三层日志

| 层 | 文件 | 内容 |
|---|---|---|
| launchd | `data/logs/launchd.*.out.log` | 进程级别，脚本没起来时看这个 |
| 脚本 | `data/logs/radar_日期_批次.log` | 批次开始/结束、交易日判断 |
| Python | `data/logs/run_日期.log` | 进度、失败明细、耗时 |

排查顺序：**从外往里**。先看 launchd 日志有没有启动，再看脚本日志走到哪一步，最后看 Python 日志。

## 健康检查：每天该确认什么

```bash
# 1. 今天的文件生成了吗
ls -la data/output/ | grep $(date +%Y%m%d)

# 2. 失败了多少只
grep "扫描完成" data/logs/run_$(date +%Y%m%d).log

# 3. 跑了多久
grep "完成，耗时" data/logs/run_$(date +%Y%m%d).log
```

正常基线（全市场约 5500 只）：

| 指标 | 正常范围 | 异常信号 |
|---|---|---|
| 失败数 | < 100 只 | > 500 只 → 接口有问题，当天数据不可用 |
| 耗时 | 4~10 分钟 | > 20 分钟 → 被限流了，调低 concurrency |
| 文件数 | 收盘批 4 个 | 少于 4 个 → 看日志哪个任务失败 |

## 缓存机制

请求结果缓存在 `data/cache/`，默认 30 分钟内复用。

作用是：**跑到一半崩了，重跑不用从头开始**。

```bash
python3 run.py --clear-cache          # 清空
python3 run.py --task 1 --no-cache    # 本次忽略缓存
```

注意：缓存 TTL 是 30 分钟，所以午盘批和收盘批不会互相污染（间隔 3.5 小时）。

## 参数调优在哪改

全部集中在 `radar/config.py`，课程里只需要认识这几个：

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `concurrency` | 12 | 经常超时/限流就调低到 6~8 |
| `qps_limit` | 30 | 同上 |
| `kline_limit` | 120 | 一般不动，改小会影响 KDJ 收敛 |
| `cv_windows` | (20, 30) | 想看不同窗口的活跃度 |
| `sentiment_universe` | hs300 | 改成 watchlist 更实用 |
| `sector_type` | concept | 想看行业板块改成 industry |
| `limit_symbols` | 0 | 调试时改成 30，或者直接用 `--limit 30` |
