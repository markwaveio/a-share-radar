# 07 咨询量与板块热度（需求 3、4）

这两个是**代理变量**。它们不如 KDJ 和成交量精确，但补上了另外两个维度：
情绪面（谁在被讨论）和资金面（钱往哪去）。

用代理变量的前提是：**先说清楚它代理的是什么、在什么情况下会失真**。

---

## 需求 3：咨询量变化

### 口径

需求原文写的是"网上咨询量"，但这个词没有官方统计口径。项目里落地为：

```text
咨询量 = 东方财富全站资讯检索，按股票名称命中的文章条数
```

对比的是：

| 窗口 | 定义 |
|---|---|
| 近期 | 过去 48 小时，换算成日均条数 |
| 基准 | 48 小时之前往前 14 天的日均条数 |
| 升温倍数 | 近期日均 ÷ 基准日均 |

### 三个必须说清的边界

**1. 它是注意力的代理，不是讨论人次**

一条被 50 家媒体转载的新闻，会记 50 条。所以它衡量的是"媒体覆盖广度"，
不是"有多少人在关心"。横向比较（谁更热）有效，绝对值意义有限。

**2. 同名误命中**

按股票名称搜索，名称含通用词的公司会被污染。
比如搜「中国平安」会命中一批只是提到"平安"的文章。

表里没法自动修正这个，所以让你建立习惯：
**升温倍数异常高的股票，点开看一眼实际新闻，再决定信不信。**

**3. 翻页截断**

单只股票最多翻 4 页 × 100 条 = 400 条。
超过的会在「是否触顶截断」列标『是』，说明**实际倍数被低估**。
这一列不能忽略 —— 最热的股票恰恰最容易触顶。

### 为什么默认只跑沪深300

全市场 5500 只 × 多页检索 ≈ 2.2 万次请求，搜索接口会限流。
默认候选池是沪深300（`sentiment_universe = "hs300"`）。

三种模式：

```bash
python3 run.py --task 3 --sentiment-universe hs300       # 默认，约 3 分钟
python3 run.py --task 3 --sentiment-universe watchlist   # 读 data/watchlist.txt
python3 run.py --task 3 --sentiment-universe all         # 全市场，预留 1 小时以上
```

**实践中最有用的是 watchlist 模式** —— 用需求 1、2、4 先筛出候选池，
把候选池写进 `data/watchlist.txt`，只查这几十只的咨询量。
既快又准，还避开了限流 —— 这是咨询量最实用的用法。

### 基准期太小的陷阱

基准期只有 2 条、近期 20 条，倍数是 10 —— 看起来很惊人，其实样本太小没有意义。

所以表里保留了「48小时内条数」和「基准期条数」两个原始计数列。
**看倍数之前先看基准期条数，小于 5 的直接跳过。**

## 需求 4：板块热度

### 口径

```text
板块热度 = 该板块当日主力净流入额 / 全市场当日主力净流入总额
```

输出 A-3、A-2、A-1、A 四个交易日，看的是**趋势**不是水平。

### 为什么看占比而不是绝对额

全市场资金总量每天都在变。同样是净流入 20 亿：

- 大盘净流出的日子 → 资金在**逆势往这个板块集中**，信号强
- 大盘普涨的日子 → 可能只是被动跟随，信号弱

占比把大盘背景剥离掉了，四天的占比序列才能横向比较。

### 分母怎么算的 —— 这一节最好的教学案例

东财没有直接给"全市场主力净流入总额"，得自己算。项目里最早用的是：

```text
全市场 = 所有【行业板块】之和        ← 这是错的
```

当时的理由听起来很合理：*东财的行业板块对 A 股是完整划分，每只股票恰好归属一个行业，
所以求和就等于全市场，而且分子分母来自同一套接口，量纲一致。*

**实测直接推翻了这个假设。** 东财 `m:90 t:2` 返回 496 个行业板块，一级二级三级混着并列：

```text
电子(423只)   元件(62只)   印制电路板(48只)   半导体(174只)   医药生物(467只)
 └── 后面三个都是「电子」的子板块，却和它平级返回
```

496 个板块的成分股数合计 **8679**，全市场只有 **5547** 只。重复计算了。

三种口径实测（2026-08-07）：

| 口径 | 分母 | 相对正确值 |
|---|---|---|
| 全市场个股逐只求和 | 364.4 亿 | **1.00×（正确）** |
| 496 个行业板块求和 | 1090.5 亿 | 2.99× |
| 504 个概念板块求和 | 6216.1 亿 | 17.06× |

**关键教学点：用错分母不会报错。**

程序照常跑完，Excel 照常生成，每一格都有数、格式漂亮、排序正常。
只是所有占比都被系统性低估 67%，而且没有任何信号提示你。

```text
程序崩了，你会知道。
口径错了，你不会知道 —— 除非你去验算。
```

正确做法：`clist` 分页拉全市场个股，`f62` 求和。56 次请求。

自己算一遍这三个数，比看十遍"要注意口径"有用。

### 历史数据从哪来

需求要 A-3~A 四天，但**没有接口能稳定给多日**：

| 接口 | 实测 |
|---|---|
| `push2his` fflow | 能给 10 天，但**间歇性**，同一分钟内时通时断 |
| `push2delay` fflow | 稳定，但只给最新 1 天 |
| 个股资金流（分母） | 只有当日 |

所以改成**本地按日快照**：每个交易日运行时存一份到 `data/flow_history/`，历史自己攒。

这是个值得讲的设计选择：**当外部依赖不可靠时，把状态挪到自己这边**。
某天接口抽风只丢那一天，不会让整张表出不来。首次部署要等 4 个交易日才有完整的表。

### 三个读表要点

| 现象 | 含义 |
|---|---|
| 占比为负 | 该板块当日主力净流出 |
| 各板块占比之和 ≠ 100%（实测约 1700%） | 正常，概念板块互相重叠 |
| 分母取了绝对值 | 全市场净流出时分母为负，取 abs 保证占比正负号只反映板块自身方向 |
| 某几格空着 | 该日快照缺分母（回填日），或该板块当天无数据 |

### 读表陷阱：属性类板块会霸榜

实测占比前十里，一多半不是题材板块：

```text
融资融券 99.9%   沪股通 59.0%   百元股 49.0%   标准普尔 41.6%   MSCI中国 39.4%
```

这些是**属性标签**，覆盖了大半个市场，必然排最前面，但没有任何方向性信息。

你关心的是「创新药 / 储能 / 光模块 / AI应用」这类**题材板块**。
读表第一件事就是跳过属性类 —— 这个第一次读表时留意。

### 概念板块 vs 行业板块

```bash
python3 run.py --task 4 --sector concept    # 默认，504 个概念板块
python3 run.py --task 4 --sector industry   # 496 个行业板块（含各级子行业）
```

你需求里举的例子（创新药、储能、光模块、AI应用）都是**概念板块**，所以默认用 concept。
行业板块更稳定、数量少，适合看中长期资金迁移；概念板块更敏感，适合看短期题材轮动。

## 这两个需求的共同教学点

代理变量的使用纪律：

1. **先定义，再使用**。说不清口径的指标不要放进决策。
2. **保留原始计数**。只给比值不给分子分母，出问题时无法诊断。
3. **标记不可靠的行**。截断、样本过小，都要在表里显式标出来。
4. **交叉验证**。咨询量升温 + 放量 + 资金流入三者同向，才值得看。
