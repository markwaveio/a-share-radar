# 12 快速上手

从零到看懂第一份报表，约 20 分钟。每一步都能自己验证结果。

---

## 1. 确认数据源能通

```bash
curl 'https://ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600000,day,,,5,qfq'
```

应该看到浦发银行最近 5 天的前复权 K 线：

```json
{"code":0,"data":{"sh600000":{"qfqday":[
  ["2026-08-07","9.260","9.210","9.290","9.140","565457.000"], ...
```

这就是整个系统的地基 —— 一个 URL，一行命令，全市场的行情数据。
字段顺序是 `日期, 开, 收, 高, 低, 量(手)`，注意是**开收高低**，不是常见的开高低收。

### 顺便看看接口挂掉是什么样

```bash
curl 'https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&klt=101&fqt=1&lmt=5&fields1=f1,f2&fields2=f51,f52,f53,f54,f55,f56'
```

写这份手册时它返回 `curl: (52) Empty reply from server`：TCP 和 TLS 握手都成功，
服务端接了连接然后直接关掉。同一时刻东财的其他接口是好的。

**第三方接口没有服务承诺。** 系统的多数据源设计就是为了这一刻 —— 它会自动切到能用的源。

还有更隐蔽的一种：

```bash
curl 'https://push2delay.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&klt=101&fqt=1&lmt=5&fields1=f1,f2&fields2=f51,f52,f53,f54,f55,f56'
```

HTTP 200、JSON 合法，但里面没有 K 线。两天内观察到两种长相：

```text
{"rc":0,  ..., "data":{"code":"600000","klines":[]}}    业务码正常但列表空
{"rc":102,..., "data":null}                              data 直接是 null
```

只判状态码挡不住，只判 `rc == 0` 也挡不住。**唯一可靠的判据是把要用的字段取出来看是不是空的。**

## 2. 跑一次链路自检

```bash
cd /path/to/a-share-radar
python3 run.py --task 1 --limit 30
```

日志里确认这四行：

| 日志 | 含义 |
|---|---|
| `全市场 A 股共 55xx 只` | 股票池拉到了 |
| `扫描完成：成功 30，失败 0` | 抓取正常，**这个失败数每天都要看** |
| `数据源命中：tencent 90次 tencent_min 90次` | 90+90=180=30只×6周期，完整 |
| `已生成 .../01_KDJ全周期_*.xlsx` | 输出正常 |

命中数对不上就是有周期在静默缺失，去查 `radar/providers.py` 的优先级链。

日志里出现 `数据源 eastmoney 连续失败 8 次，熔断 90.0 秒后重试` 是正常的 —— 熔断器
把挂掉的源摘掉，冷却后再放探针试。没有它，一个挂掉的源会让整轮跑 20 小时。

## 3. 打开 Excel，看表头

需求 1 的表头是两行合并结构，一共 **32 列 = 2 + 10 个周期 × 3**：

```text
第 1 行：个股代码 | 个股名称 | 上一月(合并3列) | 本月(3) | ... | 15分钟(3)
第 2 行：                    |  K值 D值 J值   | K值 D值 J值 | ...
```

可以自己验证：

```python
from openpyxl import load_workbook
ws = load_workbook("data/output/01_KDJ全周期_20260809_close.xlsx")["KDJ全周期"]
print(ws.max_column)                  # 32
print(len(ws.merged_cells.ranges))    # 12
```

这个结构不是设计出来的，是需求 Excel 里给定的 —— **表头就是验收标准**。

**开筛选要选中第 2 行**（K值/D值/J值 那一行）。选第 1 行会因为合并单元格失败。

## 4. 确认指标算得对

```bash
python3 tests/test_indicators.py
```

11 个测试全绿。其中 `test_kdj_matches_manual_recursion` 用手工递推的结果校验 KDJ ——
因为 KDJ 里的平滑是递推 `K = (2×前一日K + 今日RSV) / 3`，不是移动平均。
用 `rolling(3).mean()` 会算出差 10~20 的值，而且看起来"像是对的"，是最难查的一类 bug。

**然后做一次人工对照**：从表里挑 3~5 只股票，在自己的行情软件里切日线看 KDJ(9,3,3)，
对照「本日」和「上一日」的 K/D/J。

| 差值 | 判断 |
|---|---|
| < 0.05 | 通过 |
| 0.05 ~ 1 | 可接受，记录下来 |
| > 1 | 不通过，查第 13 节「KDJ 和行情软件对不上」 |

这一步不能跳过。**指标算错不会报错，只会安静给出错误结论。**

## 6. 装定时任务

```bash
./scripts/install_launchd.sh install
./scripts/install_launchd.sh status
```

装完要知道的四件事：

- **11:40 午盘批只跑需求 1**，成交量和资金流要等收盘才完整
- **15:15 收盘批四个全跑**，15 分钟缓冲是等资金流数据落库
- **非交易日自动跳过** —— 它去问上证指数今天有没有 K 线，不维护会过期的节假日表
- **开机不补跑** —— 错过的批次数据已失去时效，补跑会覆盖出错误时点的快照

## 7. 走一遍筛选流程

用当天生成的四张表，从板块往下：

```text
04 板块热度   → 挑 2~3 个 A-3→A 连续升温的方向（跳过融资融券这类属性板块）
02 放量TOP200 → 这些方向里，放量倍数 > 3 且 基准期CV < 0.6 的
03 升温TOP100 → 消息面跟上了吗（先看基准期条数，< 5 直接跳过）
01 KDJ全周期  → 月/周/日是否同向
   → 缩到 10~20 只，写进 data/watchlist.txt
```

写好 watchlist 之后：

```bash
python3 run.py --task 3 --sentiment-universe watchlist
```

这是咨询量最实用的用法：**不查全市场，只查已经筛出来的候选池**。
十几只只要几秒，又快又准，还避开限流。
